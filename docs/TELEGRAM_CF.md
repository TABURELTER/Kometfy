# Ускоритель Telegram через Cloudflare

Ускоритель (локальный MTProto-прокси на `127.0.0.1:1443`) ходит к Telegram через его веб-шлюзы
`kwsN.web.telegram.org`. Некоторые провайдеры блокируют адреса Telegram целиком (`149.154.0.0/16`,
`91.108.0.0/16`): тогда не открывается ни шлюз, ни прямое подключение к дата-центру.

На этот случай мост умеет идти через Cloudflare: он открывает тот же WebSocket на `kwsN.<ваш домен>`,
а Cloudflare пересылает его в дата-центр N. Адреса Cloudflare обычно не заблокированы. Способ взят
из tg-ws-proxy (Flowseal, MIT), идея — Nekogram/WSProxy.

Порядок: сначала шлюз Telegram, потом домены Cloudflare, потом прямой TCP. Если шлюз дата-центра не
ответил, следующие 10 минут мост сразу идёт через Cloudflare.

## Настройка домена (один раз, около 150 ₽ в год)

1. Добавьте любой домен в Cloudflare (купить там же или перенести NS-серверы).
2. `SSL/TLS` → `Overview`: режим **Flexible** (Cloudflare идёт к дата-центру по HTTP, порт 80).
3. `DNS` → `Records`: `A`-записи с включённым проксированием (оранжевое облако):

   | Name | IPv4 |
   |---|---|
   | `kws1` | `149.154.175.50` |
   | `kws2` | `149.154.167.51` |
   | `kws3` | `149.154.175.100` |
   | `kws4` | `149.154.167.91` |
   | `kws5` | `149.154.171.5` |
   | `kws203` | `91.105.192.100` |

4. В Kometfy: «Приложения» → «Ускоритель Telegram» → «Telegram не грузится? Пустите его через
   Cloudflare» → домен (`example.com`, без `kws1.`) → «Сохранить». Работающий мост подхватит его сразу.

В журнале приложения видно, чем пошло соединение: `DC2 over Cloudflare (kws2.example.com)`.

## Домен по умолчанию

Домен проекта есть только в сборке Kometfy, в открытом ядре его нет: приложение передаёт его ядру при запуске
(`prism_connect::builtin`), а в коде и файлах он не лежит открытым текстом, чтобы его не собирали поиском. Мост
пробует его после доменов пользователя, так что ускоритель работает без настройки. Сборка открытого ядра без него
ходит только через домены, которые пользователь указал сам. Записи `kws1`…`kws5`,
`kws203` и режим Flexible заведены 13 ноября 2026 года. У tg-ws-proxy есть свой публичный набор доменов,
но автор намеренно его шифрует, чтобы его не собирали и не перегружали, — мы его не берём. У Cloudflare есть лимит на
число одновременных WebSocket-подключений на домен, поэтому для многих пользователей нужно несколько
доменов.
